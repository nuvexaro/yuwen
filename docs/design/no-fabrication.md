# 防止编造没有记录的共同经历：设计说明

日期：2026-11-23 · 基于 main `84ecede` · 路线 A（改识别 + 改指令，必要时加事后检查）

## 1. 根因（有基线支撑）

`benchmark/fabrication_probe/baseline_summary.md`（q4 / q8，temperature 0，seed 42，每句 3 次）：

| 模型 | A 组编造率 | `insufficient_evidence` | `ordinary`（无护栏） | B 组漏答率 |
|---|---|---|---|---|
| yuwen-4b-q4 | 21/30 = 70% | 3/9 = 33% | 18/21 = 86% | 6/15 = 40% |
| yuwen-4b-q8 | 15/30 = 50% | 0/9 = 0% | 15/21 = 71% | 6/15 = 40% |

两个洞：

1. **识别面太窄**（主因）：`_ENTITY_REF`（`runtime/reality_boundary.py:85-89`）是城市/时间词表，
   不含「礼物 / 吵架 / 生日 / 约会 / 分手 / 牵手 / 电影」，10 条 A 组里 **7 条判成 `ordinary`，不注入任何护栏**。
   数据上，有护栏的编造率 0–33%，没护栏 71–86%——**差距几乎全来自"有没有护栏"**，不是模型不听指令。
2. **兜底只防"确认"不防"叙事"**：`_detect_confirmation`（`runtime/persona_runtime.py:232-280`）只认
   「对…/是的/去过/去了」，对「街角便利店 + 快过期可乐」这类编出来的场景不触发。

## 2. 识别环节：按句子结构判，不靠加词

新增两个确定性判定（`runtime/reality_boundary.py`）：

- **规则 A｜共同过去**：主体（`我们|咱们|咱俩|你和我|我和你`，**或交互句式 `你…我` / `我…你`**，
  **或独立出现的 `你还记得 / 还记得`**，或"`你` + 过去标记"）
  **且** 过去标记（`过|那次|那天|那会儿|那时候|第一次|当时|上回|上次|以前|之前|去年|前年|那年|那+量词`）
  **且** 经历谓词（`见面|认识|去|来|吃|看|送|买|吵|分手|旅行|约会|牵手|住|玩|等|提|留|说|答应|在一起`）。
  三段同时成立才算；命中 `还记得` 可跳过谓词要求（"你还记得那首歌吗"本身就是在问共享过去）。
- **规则 B｜个人事实询问**：`你的?(生日|老家|年龄|工作|学校|名字|身高)` 等**封闭清单**的"问事实"句式。
  **明确排除偏好类**（爱/喜欢/最/习惯/一般）——否则 B 组会从"漏答"恶化成"装不记得"。

不触发（反面清单，命中即 `ordinary`）：
- 将来时：`明天|下次|以后|待会|待会儿|要不要|好不好|打算|想去|准备|将来|下周|下个月|回头|等会儿`
  （命中即 `ordinary`，C 组「我们明天一起去看电影好不好」这类必须放行）
- 现在时：`今天|现在|正在|最近`（无过去标记时）
- 假设句：`如果|假如|要是|万一`
- 情绪/寒暄：`我好累|在干嘛|晚安`
- 纠正轮（已有分支处理）

判完再走原有五态：只有**检索不到主体相关的记忆**才升级为 `insufficient_evidence`；召回得到就是 `supported`，
B 组命中偏好时不受影响。

## 3. 生成前指令：把"没有记录"说破

当 `boundary_state = insufficient_evidence` 且属于规则 A/B 时，`boundary_guard` 换成更强的一段（仍走
`persona_constraints` 的 `[现实边界提醒]` 渲染）：

```
（现实边界）关于这件事，人格记录里没有任何内容，不要假装记得。
不要给出具体的时间、地点、物品、人物或事件经过；可以说记不清、没印象，或者反问对方。
```

**只改这一环能到什么程度（评估）**：基线里"有护栏"组的编造率是 Q8 0%、Q4 33%（Q4 的 A1 还是编了"学校图书馆"）。
若新识别把 10 条全覆盖，按该区间外推，A 组编造率大致落在 **0–30%**，中位数约 10–20%。
所以**单靠指令不够稳**，需要第 4 节的事后检查兜底，但预期它只处理少数漏网。

## 4. 事后检查（第 3 点，按需启用）

触发条件（四条同时）：
1. `boundary_active` 为真，且 `boundary_state ∈ {insufficient_evidence, unsupported_claim}`；
2. 回复**不含** hedge 词（`记不清|不记得|没印象|不确定|好像|可能`）——已经在打太极的就别动；
3. 回复里出现 **≥2 个具体实体**：年份/日期/数字、地点（`…店|…馆|…院|…路|…楼|…街`）、具体物品；
4. 这些实体在 **persona 全量 + 命中记忆 + 当前用户消息** 里都查不到（用户自己提过的不算编造）。

命中则整段替换为既有兜底话术（`……我不太确定是不是你说的那次/那年。你具体说说？`），
**不做局部删句**（删半句更容易出病句）。

防误伤：
- B 组不会触发（`supported` / `ordinary`）；
- 用户先提到"上次去外滩"→ 实体在 user_message 里，放行；
- 只有一个实体（如"去年"）不拦，避免把模糊回忆当编造；
- 只在 `max_tokens` 正常结束时判，gateway fallback 不参与。

## 6. 验收标准

- **A 组编造率**：两个模型都 **≤ 10%**（基线 70% / 50%）；≤ 5% 为理想。
  测量方式：同一 `questions.json`、同 seed、每句 3 次，人工按第 2 节口径复核。
- **B 组漏答率**：**不得高于基线 40%**（这是硬约束，防止为了不编而变傻）。
- **回归**：`run_tests.py` 31 套件全绿；`runtime/tests/test_stage59_*` 里与 boundary 相关的既有断言不得放宽。
- **不新增**：不为通过验收而调低 `_subject_related` 的宽支撑阈值。

## 7. 为什么不做路线 B（host 出口守卫）

基线显示 `ordinary` 组编造率 71–86%，根因是**压根没进边界流程**；host 层出口守卫只能"事后擦掉"，
不能阻止模型在 system 里继续被鼓励"顺着聊"，而且要在出口做叙事分类，误伤面比第 4 节更大。
路线 B 作为第 4 节的实现位置（如果在 frozen 侧不便）可以退而求其次放在
`stage6/host/production_host.py`，但**识别与前置指令必须在 runtime**，否则治不了根。

## 8. 不做什么

- 不做通用事实核查 / 不接外部知识库；
- 不修 B 组漏答（检索召回问题，另立条目）；
- 不改写 persona 渲染风格、不动 schema、不动写回；
- 不为了让指标好看去放宽判定口径；
- **暂时不用大模型做意图分类**：每轮会多一次调用（延迟 + 费用 + 离线模式不可用），留作以后的方向。
